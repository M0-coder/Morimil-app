# QA-1 — Authored Android coverage view

## Purpose

QA-1 derives an auditable coverage view for source files written by the project while preserving the complete Android Gradle Plugin/JaCoCo report introduced by QA-0.

The derived view is measurement-only. It does not introduce a coverage threshold, production-promotion claim, runtime change, release operation, Body operation, Guardian operation, Seed import, Genesis execution, activation, or birth declaration.

## Evidence model

The raw report remains authoritative and unchanged:

```text
app/build/reports/coverage/test/debug/report.xml
```

QA-1 adds:

```text
build/quality/android-authored-coverage.json
build/quality/android-authored-coverage.md
```

The JSON schema identifier is:

```text
morimil.android.authored.coverage.v1
```

## Exclusion policy

Only complete source-file entries may be excluded.

A source-file entry is classified as generated only when both conditions hold:

1. its name matches a reviewed generated-source rule;
2. the corresponding file is absent from the authored source roots under `app/src/main/java` and `app/src/main/kotlin`.

Current reviewed rules are:

- suffix `_Impl.kt`;
- suffix `_Impl.java`;
- exact name `BuildConfig.java`;
- exact name `R.java`;
- exact name `Manifest.java`.

If a generated-looking source exists in an authored source root, the analyzer fails closed instead of excluding it.

## Integrity checks

The analyzer must fail when:

- the XML cannot be parsed;
- the root report lacks non-empty instruction, branch, or line counters;
- a source-file entry is duplicated;
- the sum of all source-file counters differs from the root counters;
- generated-source subtraction produces a negative counter;
- included counters differ from raw counters minus excluded counters;
- the strict CI invocation finds no reviewed generated source exclusion.

The generated JSON records:

- raw counters;
- authored-source counters;
- every excluded source and reason;
- excluded counter totals;
- complete source inventory;
- included source files with zero line coverage.

## Residual boundary

Compiler-generated classes that share the same source file as authored Kotlin or Compose code remain included. QA-1 therefore reports an **authored-source view**, not a claim that every generated bytecode class has been removed.

This conservative boundary avoids undercounting by guessing which compiler-generated classes belong to a manually written source file.

## CI behavior

Android CI:

1. runs the quality-tool unit tests;
2. keeps generating the QA-0 raw report;
3. invokes the QA-1 analyzer;
4. checks that the JSON and Markdown outputs are non-empty and parseable;
5. preserves raw and derived reports in the existing governed artifact.

Python coverage includes the analyzer implementation but excludes its `test_*.py` source from the published denominator.

## Baseline policy

QA-1 does not enforce a percentage floor.

A later non-regression policy may be proposed only after:

- the derived view passes repeated CI runs;
- the exclusions are reviewed against the repository source tree;
- high-risk zero-coverage components are ranked;
- generated-code residuals are documented;
- any threshold is justified from measured evidence rather than selected arbitrarily.
