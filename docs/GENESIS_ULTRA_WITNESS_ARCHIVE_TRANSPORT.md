# Genesis Ultra atomic-birth witness archive transport

Status: implemented as a strict transport boundary. It does not execute birth.

## Purpose

After a Genesis Ultra candidate has been constructed and the host has recorded consent for that exact candidate, the final Body and Guardian evidence still has to enter the Android body as bytes.

`GenesisUltraAtomicBirthWitnessArchiveReader` reads that external transport without treating the archive, its manifest or any data inside it as a trust root.

The reader returns only a `GenesisUltraAtomicBirthWitnessPackage`. Full cryptographic verification remains the responsibility of `GenesisUltraAtomicBirthAuthorizationCoordinator`, which loads the Body identity root, Guardian trust anchor and host consent from authenticated local stores.

## Transport layout

The ZIP contains one reserved manifest:

```text
genesis.atomic.birth.witness.manifest.json
```

The manifest schema is:

```text
genesis.atomic.birth.witness.transport.v0.2
```

Its exact fields are:

```text
schema_version
candidate_digest
consent_digest
artifacts
journal
```

Each artifact record declares:

```text
path
kind
digest
```

Each journal record declares:

```text
path
digest
```

## Exact binding

The caller must supply locally held values for:

```text
expectedCandidateDigest
expectedConsentDigest
evaluatedAt
```

The archive is rejected unless its candidate and consent digests match the local values exactly.

`evaluatedAt` is never read from the ZIP. It is generated by the local verification flow and passed directly into the typed witness package. This prevents an archive from selecting an earlier instant to revive expired consent or Body-possession evidence.

A manifest containing `evaluated_at` is rejected as having an unknown field.

## Required artifacts

The manifest must declare exactly one of each normative artifact kind:

```text
seed_manifest
seed_signature
instance_identity
freedom_charter
initial_body_record
initial_body_registry
initial_body_key_epoch
initial_body_possession
first_memory_event
recovery_policy
birth_recovery_state
birth_state
birth_receipt
```

Unknown or additional artifact kinds are rejected.

## Archive validation

The reader:

- keeps all bytes in memory and never extracts files;
- rejects directory entries;
- rejects absolute paths, traversal, empty path segments, backslashes and drive prefixes;
- rejects duplicate ZIP entries and duplicate declared paths;
- requires an exact declared file set with no missing or unexpected files;
- requires strict UTF-8 for the manifest and journal entries;
- rejects duplicate JSON keys and unknown manifest fields;
- verifies SHA-256 for every artifact and journal file;
- parses every journal entry with the existing Genesis Ultra parser, which recomputes its structural digest;
- rejects duplicate journal sequence numbers;
- limits entry count, per-entry expansion and total expanded bytes;
- creates defensive byte copies before returning the witness package.

Default limits are:

```text
entries: 1024
per entry: 4 MiB
expanded total: 64 MiB
```

## Trust boundary

The transport manifest is not signed authority and cannot introduce a key.

The reader does not:

- accept a Body public key from the archive;
- accept a Guardian trust registry from the archive;
- read or write Room;
- read or write SharedPreferences;
- load Android Keystore material;
- record host consent;
- verify the final Ed25519 evidence graph by itself;
- issue `GenesisUltraAuthorizedAtomicBirth` by itself;
- call `execute()`;
- open onboarding or runtime.

A structurally valid transport package can still fail later because of an invalid Guardian signature, Body signature, document link, recovery policy, journal chain, expired consent or candidate mismatch.

## Current gate

Phase 3.10 connects this transport to full cryptographic authorization verification. The resulting authorization remains process-local. Atomic execution and runtime activation remain blocked.
